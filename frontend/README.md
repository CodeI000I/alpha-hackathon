# «Сигнал» — frontend

React 18 + TypeScript 5.6 + Vite 6 интерфейс персональной ленты событий для бизнеса. Проект сохраняет существующий Go API и собирается вместе с ним в один образ.

## Режимы данных

`VITE_DATA_MODE` принимает только два режима:

- `api` — значение по умолчанию; запросы идут в настоящий `/api/v1`, ошибка не заменяется моками;
- `demo` — сеть не используется; два фиксированных сценария и созданные пользователем демоданные хранятся в браузере.

Для автономного запуска:

```bash
cd frontend
npm ci
VITE_DATA_MODE=demo npm run dev
```

Для работы с Go используйте `VITE_DATA_MODE=api npm run dev`. Без переменной и без переопределения в `.env.local` режим по умолчанию — `api`. В development Vite проксирует `/api` на `http://localhost:8080`. Режим фиксируется при запуске Vite или сборке, а не меняется в уже собранном приложении.

## Точки входа и маршруты

- `/bank.html` — отдельная демонстрационная главная «Альфа-Бизнеса»; пункт «Сигнал» открывает сервис в новой вкладке и не переносит банковскую сессию или данные компании;
- `/` — переход на регистрацию или рабочий экран в зависимости от локальной сессии;
- `/landing` — справочная страница о сервисе;
- `/register` — двухшаговое создание компании и пользователя без пароля;
- `/login` — вход только в опубликованные демоаккаунты; настоящий Go API входа пока не имеет;
- `/dashboard` — сводка и лента событий;
- `/news/:itemId` — разбор события и экспорт TXT;
- `/profile?tab=roles|company|keywords|documents` — кабинет с четырьмя вкладками.

Старые адреса `/onboarding`, `/feed`, `/feed/:itemId` и `/company` перенаправляются на новые маршруты.

Логотип основного приложения ведёт в обзор, на формах входа и регистрации — на `/landing`, без перехода в демонстрацию банка. Меню аватарки содержит личный кабинет, прямые ссылки на его четыре вкладки и выход.

## Регистрация

Регистрация состоит из двух экранов. На первом пользователь вводит имя и email; переход дальше не создаёт ни компанию, ни аккаунт. На втором обязательны название компании, ИНН и хотя бы одна роль. Только финальная отправка второго шага последовательно вызывает `createCompany → createUser`. Если компания создана, а создание пользователя завершилось ошибкой, её ID сохраняется и используется при повторе без создания дубля.

Черновик полей хранится до закрытия вкладки в `sessionStorage` и разделён по режимам ключами `signal.registration-draft.v1.api` и `signal.registration-draft.v1.demo`. Он не является аккаунтом или серверной сессией.

Технические пояснения о регистрации и черновике убраны из постоянных подписей формы и остаются в документации. На странице входа список тестовых аккаунтов свёрнут по умолчанию.

## Настройки ролей

Кабинет показывает сохранённые роли. Маленькая серая кнопка «Изменить» с карандашом рядом с заголовком роли открывает диалог выбора; сохранение выполняет существующий PUT и обновляет ленту по ответу сервера. Отмена или Escape закрывают диалог без сохранения, возвращая фокус к кнопке. При отсутствии ролей кнопка называется «Выбрать».

Роль для просмотра ленты указана в шапке рядом с аватаркой. При нескольких ролях её можно переключить там же; варианта «Все роли» нет. Восстанавливается допустимый сохранённый выбор, иначе используется первая роль из профиля. Если выбранная роль удалена, автоматически выбирается первая из оставшихся. Названия берутся из каталога API, локальный выбор разделён по режиму, пользователю и компании. Суточные счётчики и подборка сводки по-прежнему учитывают все назначенные роли, а подпись «В вашем фокусе» использует `Role.focus` выбранной роли; ссылка «Мои роли» из сводки убрана.

Данные компании собраны в разделе «О компании» с понятными названиями групп. Коды и исходные сложные значения доступны в раскрывающемся разделе о данных; формат `company.profile` и запрет произвольной записи в него не менялись.

## Сводка событий

Восстановлено оформление прототипа: крупный счётчик, стрелки вниз у рисков и вверх у возможностей, пропорциональная полоса категорий. Значения вычисляются по `publishedAt` за последние 24 часа из максимум 200 полученных записей; фиксированных «4 событий» нет. Несколько ролевых разборов одной новости считаются одним событием по `news.id`, для сводки выбирается наиболее релевантный разбор. Стрелки обозначают категории, а не изменение относительно прошлого дня. Пустая сводка компактна, ошибки не заменяются нулём или демособытиями.

В подборке приоритет отдан риску и возможности, если они есть; свободные места занимают наиболее релевантные записи. Ссылки и кнопка «Открыть разбор» открывают реальные карточки. Подготовленные рекомендации и расчёты прототипа не подставляются в API-режиме: сервер должен передать их вместе с основаниями. Правила источников и отсутствующих данных сохранены; сводка не выдаётся за готовое резюме ИИ. Повторное получение пустой ленты не означает подтверждённого статуса обработки моделью — такого поля API не передаёт.

В API-режиме отсутствие карточек активной роли в успешном ответе перепроверяется каждые 15 секунд, пока вкладка видима. Бюджет — до четырёх автоматических повторов на выборку пользователя и набора ролей, а не на каждое переключение роли; ошибки и demo не запускают этот опрос. Ручная кнопка «Обновить события» и возврат во вкладку также обновляют данные. Готовность анализа за время повторов не гарантируется.

## Что является демо

Go API поддерживает компании, пользователей, роли, ленту и загрузку документов. Закладки, ключевые слова, чат, графики, виджеты и предложения банка остаются локальными функциями. Чат использует подготовленные ответы без ИИ; графики не подключены к рыночным или корпоративным источникам, банковские предложения не персонализированы сервером. Серверной синхронизации локальных функций нет, изоляция по режиму, пользователю и компании сохранена. `score` из API отображается как релевантность, а не вероятность.

По последнему запросу пользователя из UI удалены все плашки и суффиксы «Демо», а технические коды «Контекст» убраны из карточек. Ограничения доступны в нейтральных «О данных», «Об ответах» и «О предложении». Банковские операции по-прежнему недоступны, тестовые аккаунты сохранены. Режимы API/demo, их изоляция и отсутствие автоматической подмены ответов не изменены. TXT-экспорт по-прежнему явно помечает синтетические данные.

У числовых графиков, виджетов и аналитики компании остаётся короткая видимая подпись «Источник данных не подключён». Она не позволяет принять подготовленные числа за реальные показатели; подробности раскрываются в «О данных».

Счётчик ленты относится к активной роли («1 из 1»), тогда как суточная сводка объединяет назначенные роли. «Все» означает все типы событий текущей роли; пустая категория объясняет отсутствие данных и предлагает явный переход к другой назначенной роли, если нужные события там есть. Ручное обновление показывает загрузку и результат: «Лента актуальна» или «Лента обновлена».

Экспорт разбора отделяет сообщение источника, интерпретацию, гипотезы, документы компании и материалы банка. Наличие загруженного файла само по себе не означает, что он был проанализирован. В экспорт всегда добавляется дисклеймер: «Материал носит информационно-аналитический характер и не является инвестиционной рекомендацией».

## Публикация

Ветка `frontend` содержит передаваемые изменения. [Публичный сайт](https://alpha.devgit.net) обновляется отдельной цепочкой команды `main → CI → Docker → Argo CD`; push в `frontend` сам по себе его не меняет. Перенос в `main` и развёртывание выполняет команда backend. Для production используйте сборку в режиме `api`; настройка GitHub Pages в объём этой задачи не входит.
