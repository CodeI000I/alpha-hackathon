# Альфа Инсайты — frontend

Документация:

- [инструкция по фронтенду простыми словами](./FRONTEND_GUIDE_RU.md);
- [контракт и памятка для backend-разработчика](./BACKEND_INTEGRATION_RU.md).

React-интерфейс сервиса персональной новостной аналитики. Фронтенд работает в двух режимах данных и использует один и тот же UI:

- `api` — запросы идут в существующий Go API по относительному адресу `/api/v1`;
- `demo` — сеть не используется, детерминированные данные хранятся локально в браузере.

По умолчанию включён `api`-режим. Для локального просмотра без backend создайте `.env.local`:

```bash
VITE_DATA_MODE=demo
```

## Запуск

```bash
npm ci
npm run dev
```

Vite проксирует `/api` на `http://localhost:8080`. В production собранные файлы раздаёт Go-сервер с того же домена.

## Маршруты

- `/` — лендинг;
- `/onboarding` — создание компании и пользователя;
- `/feed` — лента событий;
- `/feed/:itemId` — подробный разбор события;
- `/company?tab=summary|roles|company|keywords|analytics|documents` — кабинет.

## Проверка

```bash
npm test
npm run build
npm run test:e2e
```

Playwright запускает приложение в `demo`-режиме и проверяет основные сценарии на ширинах 1440, 768 и 390 px.

Закладки, ключевые слова, аналитические графики и чат пока не имеют методов в Go API. Они сохраняются в браузере и явно помечены в интерфейсе как «Демо». Авторизация также отсутствует в текущем API: защищённые экраны используют локально сохранённый `userId`, а выход очищает эту сессию.
