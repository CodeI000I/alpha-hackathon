# Как проверить демку

## Интерфейс без ключа

Из корня репозитория, после установки frontend-зависимостей:

```sh
make demo-web
```

Откройте <http://127.0.0.1:5173/login>, нажмите «Тестовые аккаунты», подставьте
реквизиты и войдите. Доступны финансовый и операционный профили. На главном экране:

1. Поменяйте роль, откройте новость и задайте вопрос в чате.
2. Через «Добавить виджет → График из PDF» выберите отчёт, график и отдельный ряд.
3. Откройте оригинальный фрагмент и «Источник и точность». Приблизительные данные,
   подписанные значения и прогнозы обозначены отдельно.
4. Перезагрузите страницу: виджеты, порядок, закладки и демонстрационный чат сохраняются.
5. Выйдите и выберите второй аккаунт — его настройки независимы.

Графики взяты из сохранённых PDF. Лента и ответы этого режима подготовлены заранее;
внешняя модель не вызывается. Серверные бизнес-ситуации здесь недоступны. Команда
слушает только `127.0.0.1`; остановка — Ctrl+C в терминале сервера.

## Полный стек и тестовые профили

Нужны Docker с Compose, Python 3.12 с зависимостями проекта и действующий командный
ключ LLM. Создайте `.env` из `.env.example`, заполните `AI_API_KEY`, замените
`AI_SERVICE_TOKEN` и `INTERNAL_API_TOKEN`, затем выполните `make up`.
Ключ остаётся только в локальном `.env`, исключённом из Git. Для начала достаточно
двух компаний и одного пользователя на компанию; не загружайте все роли сразу,
если проверяете расход общего командного бюджета.

С активированным Python venv выполните `make demo-seed` или:

```sh
.venv/bin/python scripts/seed_demo_profiles.py --base-url http://127.0.0.1:8080
```

По умолчанию загружаются X5 (`cfo`) и РЖД (`procurement`) из
`fixtures/miro-personas/`: профиль, первый пользователь и по четыре документа.
Другой набор: `--personas beeline x5 rzd etalon`. Коллеги автоматически не создаются.
[Учётные данные и описание синтетических материалов](../fixtures/miro-personas/README.md).

Загрузчик использует настоящие HTTP-маршруты входа, регистрации, профиля и файлов.
Повторный запуск входит в созданный аккаунт, проверяет точное совпадение пользователя,
роли, названия компании и искусственного ИНН, обновляет отличающиеся поля профиля,
пропускает совпадающие файлы. Несовпадение личности или компании останавливает загрузку.
Совпадение файла определяется по имени, размеру и MIME: API списка файлов пока
не отдаёт контрольную сумму, поэтому изменение содержания без изменения этих
полей загрузчик обнаружить не может. Чужие файлы не удаляются.

Разрешены только HTTP(S)-адреса с буквальным loopback IP, например `127.0.0.1`
или `::1`. Имена хостов, credentials, query, fragment и редиректы не допускаются.
Используйте отдельную тестовую БД: пароли из фикстур опубликованы в Git.

## Новости и настоящий чат

1. Откройте <http://127.0.0.1:8080/login> и войдите в созданный аккаунт.
2. В «Личный кабинет → Документы» дождитесь статуса «Анализ завершён». Загрузка
   файла сама по себе не означает, что модель его обработала.
3. Сборщик получает пресс-релизы ЦБ, экономическую ленту Интерфакса и Frank Media
   при старте, далее раз в `INGEST_PERIOD`. Аналитика и персональная доставка
   требуют ключа и свободного бюджета. Кнопка «Обновить события» перечитывает
   готовую ленту, а не принудительно скачивает новые RSS.
4. В блоке бизнес-ситуаций откройте сформированную ситуацию и задайте вопрос в
   «Уточнить ситуацию». Например: «На какие данные нашей компании ты опираешься?»,
   «Каких данных не хватает для решения?», затем уточняющий вопрос по ответу.
5. Проверьте ссылки на основания, перезагрузку с историей, повтор после ошибки,
   смену роли и второй аккаунт. Ссылки ведут к основаниям той же версии ситуации;
   неоднозначные и неизвестные ID отображаются текстом.

Чат привязан к бизнес-ситуации и её версии. Если ситуация ещё не сформирована,
свободного общего чата с LLM в текущем API нет. После обновления ситуации старый
диалог сохраняется; для новой версии предлагается начать новый.

## Что проверено 25 октября 2026

- Реальный сбор RSS в отдельной временной БД: 14 записей ЦБ, 1 Интерфакса,
  60 Frank Media. Это результат конкретного прогона, не гарантированный размер лент.
- Настоящий Go HTTP API и PostgreSQL: созданы две компании, загружены восемь
  документов; повторный импорт не добавил документов и не обновил совпадающие профили.
  Для файлов использовался временный локальный S3-компонент из существующего
  интеграционного теста. Тестовая БД и процессы после проверки удалены/остановлены.
- Проверки виджетов и механики чата выполняются браузерными тестами с управляемыми
  API-ответами. Они не подтверждают смысловое качество ответа внешней модели.

Прогон с настоящей LLM и Docker/RustFS остаётся непроверенным: на этой машине
не предоставлен командный ключ и не установлен Docker. Этот статус нельзя заменять
результатами демонстрационного чата. После настройки требуется пройти сценарий выше.
