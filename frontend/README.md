# «Сигнал» — frontend

React + TypeScript + Vite интерфейс бизнес-аналитики. В production Go обслуживает frontend и проксирует запросы к analytics; в development Vite направляет `/api` на `http://localhost:8080`.

Подробности: [инструкция по запуску](./FRONTEND_GUIDE_RU.md), [контракт frontend/backend](./BACKEND_INTEGRATION_RU.md), [источники банковского экрана](./BANK_UI_SOURCES.txt).

## Режимы данных

`VITE_DATA_MODE` выбирается при запуске или сборке:

- `api` — режим по умолчанию. Интерфейс вызывает Go API. Ошибки и некорректные ответы показываются явно, без автоматической подмены демоданными.
- `demo` — автономные локальные fixtures; сетевых запросов нет.

```bash
cd frontend
npm ci
VITE_DATA_MODE=demo npm run dev
```

Для подключённого Go API запустите `VITE_DATA_MODE=api npm run dev`.

## Маршруты

- `/` — переход к регистрации или рабочему экрану после проверки сессии;
- `/landing` — описание сервиса;
- `/register`, `/login` — создание аккаунта и вход;
- `/dashboard` — бизнес-ситуации, сводка и лента событий;
- `/news/:itemId` — разбор события и TXT-экспорт;
- `/issues/:issueId` — бизнес-ситуация, основания, история и чат;
- `/profile?tab=roles|company|keywords|documents` — кабинет;
- `/bank.html` — изолированный демонстрационный банковский экран.

## Вход и регистрация

В `api`-режиме вход выполняется через `POST /api/v1/auth/login`; `GET /api/v1/auth/me` восстанавливает текущую сессию, а `POST /api/v1/auth/logout` отзывает её. Go устанавливает HttpOnly cookie. Браузер не хранит пароль или пользовательский ID для восстановления авторизации: действительность сессии подтверждает сервер.

Регистрация отправляет один атомарный `POST /api/v1/onboarding` с данными `company` и `user`, включая `user.password` (не менее 10 символов), а также idempotency key. Неопределённый сетевой результат можно безопасно повторить тем же ключом. Черновик хранит только поля формы; пароль и его хеш в хранилище браузера не записываются. Сервер создаёт компанию и пользователя и проверяет выбранные роли. Попытка присоединиться к существующей компании только по ИНН не допускается.

В `demo` вход и регистрация остаются локальными и не используют серверную cookie.

## Рабочая аналитика

В `api`-режиме `/dashboard` показывает серверную ситуацию и реальные issues. Карточка issue открывает детали, основания (evidence), историю изменений и пользовательское состояние. Встроенный чат закреплён за версией issue: после изменения версии пользователь может явно начать новый разговор. Кнопка обновления запускает refresh; экран отображает состояние job и статусы обработки документов (`queued`, `ready`, `failed`), включая возможность повторить обработку неудачных файлов.

Analytics-вызовы передают выбранную роль через `role`; идентификаторы компании и пользователя браузер не задаёт — область доступа выводит Go из cookie-сессии. Серверные источники и URL оснований отображаются как получены. Если запрос завершился ошибкой, интерфейс не подставляет цифры или фиктивный вывод.

Поддержанные browser proxy пути перечислены в [контракте интеграции](./BACKEND_INTEGRATION_RU.md). Часть локальных возможностей (например, ключевые слова и избранное) остаётся локальной и не меняет серверный результат.

## Терминология оценки

В рабочем API-режиме совместимость с `/rank` предоставляет ordinal-оценку срочности: `score` используется как порядок приоритета, а не вероятность и не мера релевантности. Интерфейс подписывает это как срочность/приоритет. Термин «релевантность» относится только к соответствующему demo fixture, если так подписан демоэкран.

## Проверка

Из `frontend/`:

```bash
npm test
npm run typecheck
npm run build
npm run test:e2e
```

Отдельно прошёл `scripts/test_unified.py` с настоящими Go/Python HTTP-сервисами и временной PostgreSQL БД; модель и файловое хранилище заменены тестовыми стендами. Подробности и границы проверки — в [отчёте интеграции](../docs/integration-main-2026-10-24.md).

## Публикация

Публичное развёртывание следует цепочке `main → CI → Docker → Argo CD`. Изменение в рабочей ветке само по себе не обновляет сайт. Локальная сборка и тесты не подтверждают статус удалённого CI или deploy.
