# «Сигнал»: инструкция по frontend простыми словами

Этот документ помогает запустить и показать интерфейс, а также честно объясняет границу между подключённым Go API и демонстрационными возможностями.

## 1. Где находится frontend

Репозиторий — общая папка проекта с историей изменений. В нём:

- `frontend/` — страницы и логика браузерного интерфейса;
- `backend/` — Go API, база и серверная раздача статики;
- `frontend/src/api/` — единая точка доступа frontend к API или демоданным;
- `frontend/tests/` — автоматические проверки интерфейса.

Эта работа меняет только `frontend/`. Документ не подтверждает публикацию ветки, слияние в `main` или развёртывание на сервере.

## 2. Основной путь пользователя

Прототип разделён на два документа:

1. `/bank.html` показывает синтетическую главную «Альфа-Бизнеса».
2. Пункт «Сигнал» в левом меню открывает `/register` в новой вкладке.
3. После регистрации или демонстрационного входа пользователь попадает на `/dashboard`.
4. Из ленты он открывает `/news/:itemId`, а настройки компании находятся на `/profile`.

Банковский экран — только демонстрация точки входа. Он не читает банковские cookies и не добавляет в ссылку сведения о компании, счёте или авторизации. Пункт «Сигнал» открывает новую вкладку; остальные банковские кнопки не выполняют операций.

Продающий лендинг сохранён по адресу `/landing`, но уже авторизованного бизнес-клиента не заставляют проходить через него.

Логотип в основном приложении возвращает в обзор событий, а на экранах входа и регистрации — на страницу о «Сигнале». Он не переводит пользователя в банковскую демонстрацию. В меню аватарки доступны личный кабинет, прямые ссылки на его четыре вкладки и выход.

## 3. Актуальные маршруты

| Адрес | Что открывается |
| --- | --- |
| `/bank.html` | Демонстрационная главная «Альфа-Бизнеса» |
| `/` | Переход на `/register` или `/dashboard` по локальной сессии |
| `/landing` | Описание сервиса |
| `/register` | Двухшаговое создание компании и пользователя |

| `/news/:itemId` | Подробный разбор и экспорт TXT |
| `/profile?tab=roles` | «Моя роль» |
| `/profile?tab=company` | «Компания», включая аналитические демоблоки |

В кабинете ровно четыре пользовательские вкладки: «Моя роль», «Компания», «Ключевые слова», «Документы». Отдельные старые вкладки «Сводка» и «Аналитика» не являются самостоятельными разделами. Старые ссылки `/onboarding`, `/feed`, `/feed/:itemId` и `/company` поддерживаются через перенаправление.

## 4. Два режима данных

Режим задаётся до запуска или сборки через `VITE_DATA_MODE`.

### `api` — обычный режим

Это режим по умолчанию. Поддержанные функции обращаются к существующему Go API по относительному пути `/api/v1`. Если сервер вернул ошибку или недоступен, интерфейс показывает ошибку и кнопку повтора. Автоматической подмены ответа демоданными нет.

### `demo` — автономная демонстрация

Сеть не используется вообще. Данные детерминированы относительно `22 октября 2026, 12:00 UTC`, поэтому два сценария, сводка за 24 часа и скриншоты не зависят от текущей даты или доступности сервера.

| Сценарий | Электронная почта | Пароль | Пользователь и компания |
| --- | --- | --- | --- |
| Финансы технологической компании | `finance@signal.demo` | `SignalDemo2026!` | Марина Волкова, ООО «Сигнал Технологии» |
| Операции промышленной компании | `operations@signal.demo` | `SignalDemo2026!` | Алексей Морозов, АО «Северная мануфактура» |

У сценариев разные роли и события. Публичный пароль проверяется только среди этих fixture-аккаунтов, никогда не отправляется в сеть и не записывается в локальное состояние пользователя.

Регистрация в деморежиме создаёт новый локальный профиль без пароля и с пустой лентой. Для заполненной ленты используйте тестовые аккаунты выше. Данные компаний не смешиваются даже после изменения ролей. Регистрация не создаёт новый логин для формы `/login`.

Общей плашки «Деморежим» над приложением и формами нет. Пометки «Демо» остаются рядом с демонстрационными данными и функциями. Объяснения хранения и ограничений собраны здесь и в раскрывающемся разделе кабинета «О данных и сохранении». На экране входа реквизиты доступны в свёрнутом разделе «Тестовые аккаунты».

## 5. Как запустить

В проекте Docker использует Node.js 22. Для локального запуска откройте терминал в `frontend/` и один раз установите зависимости:

```bash
npm ci
```

Автономная демонстрация:

```bash
VITE_DATA_MODE=demo npm run dev
```

Режим с Go API:

```bash
npm run dev
```

`api` включается по умолчанию. Go должен быть доступен на `http://localhost:8080`; Vite пересылает туда запросы `/api`. Терминал покажет адрес frontend, обычно `http://localhost:5173`. Для показа полного пути начните с `http://localhost:5173/bank.html`.

Не открывайте `index.html` двойным щелчком как `file://…`: исходники React нужно запускать через Vite. Готовая сборка создаётся командой `npm run build`, а локально посмотреть её можно через `npm exec vite preview`.

### Код на GitHub и работающий сайт — разные вещи

[Ветка frontend на GitHub](https://github.com/CodeI000I/alpha-hackathon/tree/frontend/frontend) показывает код и эти инструкции. Наличие кода на GitHub само по себе не публикует работающий сайт. Для публичной ссылки команда должна развернуть общий Docker-образ с Go либо отдельно согласовать хостинг демосборки. В этой работе GitHub Pages и внешний хостинг не настраиваются.

## 7. Регистрация и сессия

Форма `/register` разделена на два шага:

1. Пользователь вводит имя и email. Кнопка «Продолжить» только проверяет эти поля и открывает следующий экран: компания и аккаунт на сервере ещё не создаются.
2. Пользователь обязательно указывает название компании, ИНН и выбирает хотя бы одну роль. Можно выбрать несколько ролей; их названия всегда приходят из `/roles` или из полного девятиролевого demo fixture. Старого жёсткого набора из трёх ролей нет.

Только кнопка завершения второго шага сначала создаёт компанию, затем пользователя. После первого успешного запроса ID компании сохраняется. Если второй запрос завершится ошибкой, повтор создаст только пользователя и не продублирует компанию. После успеха промежуточный ID очищается.

Поля и текущий шаг сохраняются в режиме-специфичном черновике `sessionStorage`. Перезагрузка той же вкладки восстанавливает черновик; закрытие вкладки удаляет его. Это локальный черновик, а не созданный аккаунт. Уже созданный после финальной отправки промежуточный `companyId` хранится отдельно, поэтому закрытие вкладки не удаляет компанию с сервера.

В `api`-режиме пароль отсутствует, потому что текущий Go API не имеет авторизации. Сохранённый `userId` — удобство прототипа, а не защита данных. Выход очищает только локальную сессию.

Под формами больше нет постоянных технических пояснений о черновике и серверных запросах. Это изменение текста и оформления, а не логики регистрации: сохранение черновика, проверка полей и восстановление после ошибки продолжают работать.

## 8. Сводка, лента и разбор

`/dashboard` получает не более 200 элементов и поддерживает:

- события для роли, выбранной в шапке рядом с аватаркой;
- поиск по заголовку, сообщению источника, интерпретации, источнику и элементам профиля;
- фильтры «все», «риски», «возможности», «события» и локальные закладки;
- отдельные состояния загрузки, пустой выдачи и ошибки;
- сводку последних 24 часов.

В шапке всегда показано конкретное название роли. Если у вас несколько ролей, их можно переключать там же. Выбор «Все роли» отсутствует; при первом открытии выбирается первая роль из вашего профиля. Сохранённый выбор восстанавливается отдельно для текущего режима, пользователя и компании. Если выбранную роль удалили, отображается первая из оставшихся.

Суточная сводка охватывает все назначенные роли и не меняется от выбранной роли, поиска или фильтров ленты. Она рассчитывается по `publishedAt` из максимум 200 полученных записей, а не генерируется ИИ. Ссылки «Мои роли» внутри сводки нет. При неудачном обновлении уже полученные данные остаются на экране с предупреждением.

Прямая ссылка `/news/:itemId` загружает ленту с лимитом 200 и ищет элемент по ID; при переходе из обзора может использоваться общий свежий кеш. Отдельного endpoint для одной карточки сейчас нет.

### Правила источников и формулировок

- `news.summary` показывается как сообщение источника, а не как вывод банка.
- `insight` показывается как интерпретация для роли.
- Отдельные гипотезы, сценарии и расчёты не объявляются фактами, если сервер их не передал.
- Источник строится только из настоящих `sourceId` и `url`; кликабельны только `http`/`https` ссылки.
- Неизвестный источник, дата или релевантность так и обозначаются; логотипы и организации не выдумываются.
- `score` допустим в диапазоне `0…1` и называется релевантностью. Это не вероятность события.
- Загруженный документ не считается использованным в анализе, пока API не сообщит об этом явно.
- В `demo` указано: «Аналитика Альфа-Банка не использована в этом разборе».
- В `api` указано: «Сведения об использовании аналитики Альфа-Банка не переданы сервером.»

TXT-экспорт повторяет это разделение и не включает локальные ответы чата, закладки, графики или предложения банка в аналитический вывод. Для демоданных экспорт начинается предупреждением «ДЕМО: синтетические данные, не использовать для принятия решений.». В конце всегда добавляется:

> Материал носит информационно-аналитический характер и не является инвестиционной рекомендацией

## 9. Кабинет

- «Моя роль» показывает уже выбранные роли. Рядом с заголовком «Ваша роль в компании» находится маленькая серая кнопка «Изменить» с карандашом: она открывает отдельное окно выбора. «Сохранить роли» отправляет изменения через `PUT /users/{id}/roles`; «Отмена» или Escape закрывают окно без сохранения. После закрытия фокус возвращается к кнопке. Если роли ещё не выбраны, кнопка называется «Выбрать».
- «Компания» показывает реквизиты и раздел «О компании» только для чтения. Группы названы понятнее: «Сведения о компании», «Деятельность и финансы», «Регионы работы и поставок», «Рынок и регулирование». Технические коды полей скрыты; названия сведений берутся из справочника. Иллюстративная аналитика внутри раздела имеет маркировку «Демо».
- «Ключевые слова» работают локально и не меняют серверную ленту.
- «Документы» в `api` загружает файл multipart-полем `file` и обновляет настоящий список. Успешная загрузка подтверждает хранение, но не обработку моделью. В `demo` сохраняются только метаданные; содержимое не сохраняется и никуда не отправляется.

Если сервер прислал данные компании в ещё не согласованном сложном формате, интерфейс не придумывает их значение. Полный ответ можно раскрыть в «О данных и сохранении» → «Полученные данные компании». Редактирование этих сведений появится после согласования формата с backend-командой.

## 10. Что хранится в браузере и как изолировано

API и demo никогда не разделяют одну сессию:

- `signal.session.v2.api.userId` и `signal.session.v2.demo.userId` — текущий пользователь;
- `signal.session.v2.api.pendingCompanyId` и `signal.session.v2.demo.pendingCompanyId` — незавершённая регистрация;
- `signal.registration-draft.v1.api` и `signal.registration-draft.v1.demo` в `sessionStorage` — поля и шаг локального черновика регистрации до закрытия вкладки;
- `signal.demo-api.v2` — компании, пользователи и метаданные файлов полного деморежима;
- `alpha.insights.v2.{api|demo}.company.{companyId|none}.user.{userId}.{name}` — локальные пользовательские настройки.

Ключи старой версии `alpha.userId` и `alpha.pendingCompanyId` намеренно не мигрируются. Локальные настройки синхронизируются между компонентами и вкладками одного браузера и перезагружаются при смене пользователя, компании или режима. Очистка данных сайта удалит их; между устройствами они не синхронизируются.

Демонстрационные виджеты и скрытые предложения банка также имеют отдельные локальные ключи. Они управляют только представлением. Для них мгновенная синхронизация между открытыми вкладками не гарантируется: при необходимости обновите страницу.

## 11. Проверка перед передачей

Команды запускаются из `frontend/`:

```bash
npm test
npm run typecheck
npm run build
npm run test:e2e
```

Результат на 22 октября 2026: 109/109 unit-тестов, 35/35 браузерных сценариев, TypeScript и production-сборка проходят. Проверены клавиатура, возврат фокуса после закрытия диалогов, отсутствие горизонтальной прокрутки на 1440, 768 и 390 px, низкие окна 390×520 и 1440×500. Неожиданных ошибок консоли нет. Сборка содержит обе HTML-страницы. Новые проверки охватывают меню аватарки, переходы на главную «Сигнала», свёрнутые тестовые реквизиты, выбор роли в шапке и компактную ссылку редактирования рядом с заголовком роли.

Проверка API пока контрактная: браузерные тесты подставляют контролируемые ответы и проверяют отправленные запросы. Живой Go и общий Docker-образ не запускались, поскольку Docker и Go отсутствуют в проверочной среде. Богдану остаётся пройти реальную интеграцию на своей среде. Frontend не требует изменений Dockerfile.
