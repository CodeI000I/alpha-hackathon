# ADR-001: единый Go/React/Python контур

Статус: принято. Дата: 2026-10-24.

## Контекст

В main появился Signal и новый Go-контракт ранжирования, а ai-orchestrator содержал
изолированную аналитику и исправления очередей. Требуется сохранить обе части,
не создавать второй inference pipeline и защитить данные компаний при интеграции.

## Решение

1. Go остаётся внешним API, владельцем компаний/пользователей/S3 и раздаёт SPA.
   Bcrypt-пароли и непрозрачные PostgreSQL-сессии заменяют доверие к localStorage ID.
   JWT не нужен: сервер всё равно проверяет пользователя, сессии легко отозвать.
2. Закрытый Python host адаптирует `/rank` к `AnalyticsService` и регистрирует
   готовый router. Go проверяет владельца и роль; браузер не выбирает company scope
   и не получает служебный токен.
3. Кеш и модельные политики остаются в Python. Go сохраняет `news_deliveries` с
   fencing; миграции main не удаляются. Объединение ролей компании и Python кеш
   исключают необходимость второго модельного кеша и его правил актуальности.
4. Python worker читает Go-метаданные read-only и скачивает оригиналы через Go.
   Новый S3 SDK не нужен. Состояния sync и job leases сохраняются в PostgreSQL;
   открытие страницы не запускает извлечение документов или анализ новостей.
5. Используем существующие PostgreSQL, pgvector и сервисы. Отдельные брокер,
   identity provider и parser API-служба для этого прототипа не требуются.

## Последствия

Изменение колонок companies/company_files/users требует обновить read-only адаптер
и сквозной тест. Backup включает PostgreSQL, S3 и копии оригиналов на analytics PVC.
RWO PVC требует совместимого размещения Python API и worker; расширение на несколько
узлов потребует соответствующего общего хранилища.

Старым аккаунтам оператор назначает пароль. Дубли email, отличающиеся регистром,
блокируют миграцию до явного решения оператора: автоматически выбирать одну
личность нельзя. Рассылка приглашений и восстановление пароля по email не добавлены.

Тесты используют реальные Go/Python HTTP и PostgreSQL, синтетические LLM/S3
адаптеры. Их успех не подтверждает доступность боевого шлюза, источников или
состояние k3s: это проверяется при запуске в конкретном окружении.
