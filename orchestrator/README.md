# Оркестратор новостной аналитики

Новый прототип по спецификации «Альфа-Будущее» с PostgreSQL, документами, графом,
BusinessIssue и SituationSnapshot находится в [analytics/README.md](analytics/README.md).
Он запускается отдельно; ниже описан сохранённый совместимый `/rank`-контур.

Проверенный банком материал + снимок компании → retrieval → типизированная оценка →
готовый персонализированный разбор → сохранение. Открытие карточки только читает;
чат делает отдельный запрос. Используется существующая топология пяти LangGraph-графов.

## Запуск

Из корня репозитория, Python 3.11+:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r orchestrator/requirements.txt
.venv/bin/python -m unittest discover -s orchestrator/tests -v
.venv/bin/python -m orchestrator demo
```

Тесты и `demo` работают через mock API без ключа и сети. Demo не читает `.env.local`,
создаёт временную БД и удаляет её при завершении. Зависимости закреплены; проверено
на Python 3.15. Пример входа: `examples/bank-request.json`.

Настройки читаются из корневого `.env.local`; переменные процесса имеют приоритет.
Для нового клона скопируйте `.env.example` в `.env.local`, выполните `chmod 600 .env.local`
и заполните `AI_API_KEY`. Для HTTP нужен также случайный `AI_SERVICE_TOKEN`.
Оба секрета остаются на сервере. `.env.local`, окружение Python и данные исключены
из Git и Docker context. Существующий локальный файл не заменяйте.

```bash
# Без сети; проверяет настройки и наличие ключа.
.venv/bin/python -m orchestrator check-config
# Внутренний сервис на 127.0.0.1:8091; сам запуск не вызывает модели.
.venv/bin/python -m orchestrator serve
# Только постановка заданий, без LLM.
.venv/bin/python -m orchestrator submit --file orchestrator/examples/bank-request.json
```

Следующие команды обращаются к реальному API и расходуют общий бюджет:

```bash
# Опциональная проверка: одна короткая попытка, без retries.
.venv/bin/python -m orchestrator smoke
# Один проход очереди; периодический запуск организует backend/deployment.
.venv/bin/python -m orchestrator worker
# Синхронный сквозной запуск; rank вместо analyze возвращает Go []Match.
.venv/bin/python -m orchestrator analyze --file orchestrator/examples/bank-request.json
```

`retry JOB_ID` возвращает failed-задание в очередь после устранения причины.
У `smoke` лимит 64 выходных токена: пустой/обрезанный ответ считается ошибкой,
поэтому это проверка соединения, а не качества модели.

## Модели и ограничения расходов

Jev не используется. `LLMClient.structured()` вызывает Chat Completions шлюза
`https://changellenge.up.railway.app/v1` и проверяет JSON через Pydantic.
Шесть допустимых имён моделей перечислены в `.env.example`; по умолчанию выбран
`deepseek/deepseek-v4.1-flash`. `AI_DECISION_MODEL`, `AI_ANALYSIS_MODEL`, `AI_CHAT_MODEL`
переопределяют его для этапа. JSON mode/tools/embeddings от шлюза не требуются.

По умолчанию: timeout 60 секунд, максимум 2 retries, задержка до 15 секунд,
2 одновременных запроса на клиент, 20 запросов/минуту на общую локальную БД,
1800 выходных токенов, 32000 символов полного запроса. SDK retries выключены.
Временные ошибки повторяются ограниченно; учитывается `Retry-After`.
Ошибка ключа, неверный JSON или выдуманная ссылка не запускают платный ремонт.

Лимит **500 ₽/сутки на всю команду** контролирует шлюз. При исчерпании бюджета
вызовы блокируются до 03:00 МСК, в том числе после перезапуска. Расходы других
участников и цены моделей неизвестны: локальный код не обещает точного счётчика
рублей. Сохраняются статус вызова и usage, без ключа и исходного ответа шлюза.

Обычный релевантный разбор требует 2 вызова: оценка + текст. Нерелевантный — 1;
без фактов компании — 0. Только новые основания допускают одну дополнительную
оценку. Повторы входа, чтение и успешные этапы используют сохранённый результат.
Чат — один вызов по вопросу; передаются последние 12 сообщений.

## Контекст, оценка и версии

`RankRequest` сохраняет Go-формат `news`, `company`, `roles`. Дополнительно принимаются:

- `news.body`, `situationId`, `modality` (`reported/announced/completed/unknown`),
  `asOf`; даты требуют часовой пояс, дата анализа по умолчанию — `publishedAt`.
- `company.facts`: `id`, `text`, `source`, `sourceVersion`, необязательные `element`,
  `validFrom`, `validTo`, `observedAt`, `modality` (`current/planned/hypothesis/historical`).
  Ссылка вида `company-file:42#page=3` должна приходить от парсера реального документа.
- `company.profile`: существующий JSONB, включая коды элементов компании.
  Его источник обозначается как поле профиля, без выдуманной ссылки на документ.

Retrieval использует BM25Plus и русский стемминг. Совпадения дополняются бизнес-фактами,
чтобы отсутствие общих слов не отсекало косвенную связь. Учитываются даты фактов;
сохраняются источники, версии, модальность и количество не вошедших оснований.
Новость не обрезается молча; слишком большой запрос получает `input_limit`.
Это лексический baseline с ограниченным top_k, без гарантии полноты. Graphify,
embeddings и парсер PDF не обязательны для запуска и здесь не реализованы.
Заменяемая граница — `Retriever.retrieve()` и его `version`.

`Assessment` содержит 11 типизированных ответов: relevance, link_evidence_status,
relation_kind, risk_supported, opportunity_supported, potential_impact_band,
urgency_band, effect_horizon, primary_channel, strongest_company_fact,
strongest_candidate_link. Последний равен `not_listed/none`: отдельный генератор
гипотез пока не подключён. Score/confidence не являются вероятностью будущего убытка.
Пороги 0.35/0.7 — начальные настройки, требующие проверки на размеченных данных.

Готовый report разделяет факты, позицию банка, выводы, риски, возможности,
действия и пробелы. Условный полезный разбор публикуется с `publication=conditional`,
явным условием и одним уточняющим вопросом. Отсутствие несущественных цифр само
по себе не скрывает разбор. Противоречивые/необоснованные выводы остаются `uncertain`.
Проверяются структура и ссылки, а не истинность каждого вывода модели.

SQLite хранит снимки входов, jobs, оценки, разборы, основания и чаты. Ключ задания
включает версии новости/компании, роль и hash политики (prompts, схемы, модели,
retrieval, пороги). Новая версия не перезаписывает старую. Ответ чтения содержит
`current`, `history`, `changes`, `user_state`; внутренний graph state не выдаётся.

`situationId` связывает материалы; адаптер передаёт актуальный контекст ситуации.
Автоматической кластеризации/объединения статей нет. Известная старая версия не
откатывает текущую; неизвестные ревизии принимаются по порядку доставки, поэтому
адаптер должен упорядочить их. Изменение компании запускает `refresh`.
Персональные `open/watching/closed`, закрепление и прочитанность сохраняются при
обновлениях. Чат закреплён за версией разбора; сценарии не изменяют факты компании.

Claim атомарный, lease — час, максимум 3 запуска задания. Failed повторяется явно;
budget_exceeded доступен следующему worker после `retry_at`. Просроченный worker
не перезапишет результат нового. Падение между ответом API и записью cache может
повторить платный вызов. SQLite подходит одному хосту; для нескольких подов нужны
общее хранилище, очередь и лимиты. LangGraph управляет переходами, job/cache — восстановлением.

## API и подключение команды

Кроме `/healthz`, API требует `Authorization: Bearer <AI_SERVICE_TOKEN>`.
Для чтения, состояний и чата backend после проверки прав передаёт `X-User-ID` и
`X-Company-ID`. Эти заголовки не заменяют пользовательскую авторизацию backend.

| Endpoint | Результат |
| --- | --- |
| `POST /v1/jobs` | `RankRequest` → 202 + job_ids, без LLM |
| `GET /v1/jobs/{id}` | Статус, разбор, основания, версии и состояние; без LLM |
| `POST /v1/companies/refresh` | `{company, roles}` → задания после изменения компании |
| `PATCH /v1/jobs/{id}/state` | `{workflow?, pinned?, mark_read?}` → персональное состояние |
| `POST /v1/jobs/{id}/chat` | `{conversation_id, question}` → ответ с основаниями |
| `GET /v1/conversations` | Последние 20 созданных чатов пользователя в компании |
| `GET /v1/conversations/{id}` | Сохранённые сообщения и версия разбора; без LLM |
| `POST /rank` | Синхронный `RankRequest → []Match`, готовый report сохраняется |

Техническая ошибка возвращает 429/503, а не пустую ленту. Путь для потока:
приём новости → `/v1/jobs` → worker → чтение готового результата → запись feed_items.

Для реального потока остаётся подключить банковский источник с ID/ревизиями и
полным текстом, парсер документов компании, фоновую доставку/retry, backend ACL
и отображение report/history/chat. `backend/internal/ingest/alfa.go` пока заглушка;
Go `NewsItem.Body` не сериализуется в нынешнем контракте, его нужно передавать явно.

В `origin/backend` клиент уже использует `ORCHESTRATOR_URL` и `/rank`, но не
отправляет служебный токен и ограничен 60 секундами. Для готового разбора из нескольких
LLM-вызовов нужен фоновый путь jobs либо согласованный timeout. Ingest пока пропускает
повторы новости; UpsertNews обновляет лишь title, AddFeedItem не обновляет конфликт.
Команде нужно связать версии и обновление карточки. Go/frontend/deployment здесь не меняются.
