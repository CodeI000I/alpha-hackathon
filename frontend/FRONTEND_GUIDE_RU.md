# Фронтенд «Альфа Инсайты»: инструкция простыми словами

Этот файл объясняет, что уже сделано, как посмотреть сайт и какие части пока работают в демонстрационном режиме. Технические знания для чтения не нужны.

## 1. Что такое репозиторий и где находится сайт

Репозиторий — это общая папка проекта, которая хранится в GitHub вместе с историей изменений. В этом проекте:

- `frontend/` — внешний вид сайта и всё, с чем взаимодействует пользователь;
- `backend/` — серверная часть, база данных и обработка информации;
- ветка `frontend` — отдельная версия проекта, в которой сейчас находится новый интерфейс;
- ветка `main` не изменялась.

Новый фронтенд уже отправлен в ветку `frontend` на GitHub.

## 2. Что уже реализовано

### Главная страница

Адрес: `/`

Это презентационная страница продукта. На ней объясняется:

- зачем нужен сервис;
- какие задачи он решает;
- как новость превращается в риск, возможность или действие;
- как перейти к созданию профиля или вернуться в уже созданную ленту.

### Регистрация и настройка профиля

Адрес: `/onboarding`

Пользователь вводит:

- имя;
- электронную почту;
- название компании;
- ИНН;
- одну или несколько управленческих ролей.

Пароля и фиктивной формы входа нет, потому что настоящий механизм авторизации пока отсутствует в backend.

При отправке формы фронтенд сначала создаёт компанию, затем пользователя. Если компания уже создалась, а создание пользователя завершилось ошибкой, фронтенд запоминает компанию и при повторной попытке не создаёт её второй раз.

### Лента событий

Адрес: `/feed`

В ленте можно:

- смотреть события для всех выбранных ролей или отдельной роли;
- искать по заголовкам, описанию, объяснению, источнику и элементам профиля;
- фильтровать события, риски и возможности;
- видеть релевантность каждого события;
- открывать подробный разбор;
- сохранять карточки в локальные закладки.

У ленты есть состояния загрузки, ошибки и отсутствия данных. Если сервер недоступен, пользователь увидит ошибку — скрытой подмены серверных данных демоданными нет.

### Подробный разбор события

Адрес: `/feed/ID`, например `/feed/101`

Страница показывает:

- заголовок и краткое содержание новости;
- тип события;
- управленческую роль;
- релевантность;
- объяснение, почему событие важно;
- связанные элементы профиля компании;
- реальную ссылку или идентификатор источника, если backend их передал.

Источник, логотип или сведения об организации не придумываются. Если сервер не передал источник, отдельный блок источника не показывается.

На странице также есть демонстрационные блоки возможного влияния, следующих шагов и чата. Они явно помечены словом «Демо».

### Личный кабинет

Адрес: `/company`

В кабинете есть шесть разделов:

1. `Сводка` — пользователь, компания, количество ролей, элементов профиля и документов.
2. `Мои роли` — выбор нескольких ролей и сохранение через настоящий серверный запрос.
3. `Компания` — название, ИНН, ОГРН и существующие элементы профиля из backend.
4. `Ключевые слова` — локальная демонстрационная функция.
5. `Аналитика` — демонстрационные графики и показатели.
6. `Документы` — настоящая загрузка файла в backend в обычном режиме и локальная имитация в деморежиме.

Фронтенд не изменяет `company.profile`: формат значений внутри этого поля должен сначала согласовать backend-команда.

### Выход

Кнопка «Выйти» удаляет сохранённый в браузере `userId` и возвращает пользователя на главную страницу. Серверная авторизация и настоящие пользовательские сессии пока не реализованы.

## 3. Что работает по-настоящему, а что является демо

| Возможность | Обычный режим | Деморежим |
| --- | --- | --- |
| Справочник ролей | Загружается из Go API | Берётся из фиксированного набора |
| Создание компании | Отправляется в Go API | Сохраняется в браузере |
| Создание пользователя | Отправляется в Go API | Сохраняется в браузере |
| Изменение ролей | Настоящий `PUT`-запрос | Сохраняется в браузере |
| Лента и профиль компании | Загружаются из Go API | Берутся из фиксированных данных |
| Документы | Загружаются в backend | Имитируются локально |
| Закладки | Хранятся в браузере, «Демо» | Хранятся в браузере, «Демо» |
| Ключевые слова | Хранятся в браузере, «Демо» | Хранятся в браузере, «Демо» |
| Чат | Подготовленные локальные ответы, «Демо» | Подготовленные локальные ответы, «Демо» |
| Графики | Иллюстративные данные, «Демо» | Иллюстративные данные, «Демо» |

## 4. Как посмотреть сайт без backend

Понадобится установленный Node.js версии 20 или новее.

1. Откройте программу «Терминал».
2. Перейдите в папку `frontend`.
3. Создайте файл `.env.local` и добавьте в него строку:

```text
VITE_DATA_MODE=demo
```

4. Один раз установите зависимости:

```bash
npm ci
```

5. Запустите сайт:

```bash
npm run dev
```

6. Терминал покажет адрес, обычно `http://localhost:5173`. Откройте его в браузере.

Чтобы остановить сайт, вернитесь в терминал и нажмите `Ctrl+C`.

## 5. Как запустить сайт вместе с backend

В `.env.local` укажите:

```text
VITE_DATA_MODE=api
```

Или удалите этот файл: режим `api` используется по умолчанию.

Backend должен работать на `http://localhost:8080`, затем фронтенд запускается командой:

```bash
npm run dev
```

Фронтенд отправляет запросы на `/api/v1`, а локальный Vite автоматически пересылает их на Go-сервер.

## 6. Как проверить, что всё работает

Из папки `frontend` выполняются три команды:

```bash
npm test
npm run build
npm run test:e2e
```

- `npm test` проверяет отдельные функции;
- `npm run build` проверяет TypeScript и собирает production-версию;
- `npm run test:e2e` открывает сайт в настоящем браузере и проходит основные пользовательские сценарии.

На момент подготовки этой инструкции проходят 26 unit-тестов и 8 браузерных сценариев.

## 7. Что хранится только в вашем браузере

До появления серверной поддержки браузер сохраняет:

- идентификатор текущего пользователя;
- незавершённую регистрацию после создания компании;
- закладки;
- ключевые слова;
- историю демонстрационного чата;
- данные, созданные в полном деморежиме.

Эти данные не синхронизируются между компьютерами. Очистка данных сайта в браузере удалит их.

## 8. Что пока не реализовано

- настоящая авторизация, пароль и восстановление доступа;
- серверные закладки;
- серверное хранение ключевых слов;
- настоящий AI-чат;
- настоящие аналитические показатели и прогнозы;
- редактирование названия, ИНН и ОГРН;
- редактирование `company.profile`;
- удаление и скачивание загруженных документов.

Все отсутствующие серверные функции либо не показываются, либо явно отмечены как «Демо».

## 9. Что говорить разработчику, если нужны изменения

Чтобы задачу поняли правильно, достаточно описать четыре вещи:

1. На какой странице нужно изменение.
2. Что пользователь должен увидеть или сделать.
3. Должны ли данные сохраняться после перезагрузки.
4. Должен ли backend хранить эти данные или пока достаточно деморежима.

Пример: «На странице личного кабинета в разделе документов нужна кнопка удаления. После нажатия файл должен удаляться из backend и исчезать из списка».

## 10. Основные файлы

- `src/App.tsx` — маршруты и общая логика входа/выхода;
- `src/pages/` — страницы сайта;
- `src/components/` — повторно используемые элементы интерфейса;
- `src/api/client.ts` — все запросы к backend;
- `src/api/types.ts` — формат данных между frontend и backend;
- `src/api/mocks.ts` — фиксированные данные деморежима;
- `src/styles/` — цвета, размеры и адаптивный дизайн;
- `tests/` — автоматические проверки.

Если нужно только изменить текст, цвет или расположение элементов, backend обычно не требуется. Если нужно сохранять новые данные для всех устройств и пользователей, потребуется новый или изменённый API-метод.
