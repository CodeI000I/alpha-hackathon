# «Сигнал» — frontend

React 18 + TypeScript 5.6 + Vite 6 интерфейс персональной ленты событий для бизнеса. Проект сохраняет существующий Go API и собирается вместе с ним в один образ.

## Режимы данных

`VITE_DATA_MODE` принимает только два режима:

- `api` — значение по умолчанию; запросы идут в настоящий `/api/v1`, ошибка не заменяется моками;
- `demo` — сеть не используется; два фиксированных сценария и созданные пользователем демоданные хранятся в браузере.

Для автономного запуска:

```bash
cd frontend
printf 'VITE_DATA_MODE=demo\n' > .env.local
npm ci
npm run dev
```

Для работы с Go удалите `.env.local` или укажите `VITE_DATA_MODE=api`. В development Vite проксирует `/api` на `http://localhost:8080`.

## Точки входа и маршруты

- `/bank.html` — отдельная демонстрационная главная «Альфа-Бизнеса»; пункт «Сигнал» открывает сервис в новой вкладке и не переносит банковскую сессию или данные компании;
- `/` — переход на регистрацию или рабочий экран в зависимости от локальной сессии;
- `/landing` — справочная страница о сервисе;
- `/register` — двухшаговое создание компании и пользователя без пароля;
- `/login` — вход только в опубликованные демоаккаунты; настоящий Go API входа пока не имеет;
- `/dashboard` — сводка и лента событий;
- `/news/:itemId` — разбор события и экспорт TXT;
- `/profile?tab=roles|company|keywords|documents` — кабинет с четырьмя вкладками.

Старые адреса `/onboarding`, `/feed`, `/feed/:itemId` и `/company` перенаправляются на новые маршруты.

## Регистрация

Регистрация состоит из двух экранов. На первом пользователь вводит имя и email; переход дальше не создаёт ни компанию, ни аккаунт. На втором обязательны название компании, ИНН и хотя бы одна роль. Только финальная отправка второго шага последовательно вызывает `createCompany → createUser`. Если компания создана, а создание пользователя завершилось ошибкой, её ID сохраняется и используется при повторе без создания дубля.

Черновик полей хранится до закрытия вкладки в `sessionStorage` и разделён по режимам ключами `signal.registration-draft.v1.api` и `signal.registration-draft.v1.demo`. Он не является аккаунтом или серверной сессией.

## Демоаккаунты

Доступны только при `VITE_DATA_MODE=demo`:

| Сценарий | Логин | Пароль |
| --- | --- | --- |
| Финансы технологической компании | `finance@signal.demo` | `SignalDemo2026!` |
| Операции промышленной компании | `operations@signal.demo` | `SignalDemo2026!` |

Пароль — публичная часть fixture. Он проверяется только локально, не отправляется в сеть и не сохраняется в состоянии демопрофиля. Регистрация нового демопрофиля остаётся беспарольной.

## Что является демо

Go API поддерживает компании, пользователей, роли, ленту и загрузку документов. Закладки, ключевые слова, чат, графики, виджеты и предложения банка остаются локальными функциями с заметной маркировкой «Демо». `score` из API отображается как релевантность, а не вероятность.

Экспорт разбора отделяет сообщение источника, интерпретацию, гипотезы, документы компании и материалы банка. Наличие загруженного файла само по себе не означает, что он был проанализирован. В экспорт всегда добавляется дисклеймер: «Материал носит информационно-аналитический характер и не является инвестиционной рекомендацией».

- Ширины 1440, 768 и 390 px, окна 390×520 и 1440×500, клавиатура, диалоги, Escape и возврат фокуса — проверены. Неожиданных ошибок консоли нет; в негативных API-тестах ожидаемые HTTP 404/503 проверяются отдельно.

API-сценарии используют перехваченные тестовые ответы и проверяют формы реальных запросов — это **не проверка живого Go**. Docker и Go не установлены в проверочной среде, поэтому запуск общего образа и интеграционный сценарий с живым backend не выполнены. Структура сборки сверена с существующим Dockerfile и Go-раздачей статики; инфраструктура не менялась. Локальные проверки выполнены на Node.js 24.21.0; Dockerfile по-прежнему использует Node.js 22.
